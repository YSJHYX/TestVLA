# RM65 + SG100：6+6+5 接入

本地修改基于官方提交 `89f2322b4ad016e192437adc1a2c253b05bab246`。保持官方27维网络、九维共享codec、码本与group tokens；保留AR、FM、CoT和原生visual memory。不转换现有LeRobot v2.1数据，不在线生成CoT标签。

## 输入契约

- `action`与`observation.state`各17维、弧度；action是生效命令，state是实测反馈。动作读取offset=0。
- 通道顺序：RM65六关节，SG100 J1–J11；手部已经是SDK-user坐标域，不再翻转符号。
- RGB键为`observation.images.head`和`observation.images.wrist`；wrist按用户确认映射为左手腕。右手腕使用原生黑图dummy。原数据wrist已旋转，勿再旋转。
- `tasks.jsonl`中的原任务指令直接使用。没有CoT标签时MixedSamplesBuilder选择基础动作样本；有可靠标签时仍可使用已有CoT格式。

| 原通道 | 模型组 | 处理 |
|---|---|---|
| [0:6] 手臂 | right_control(9) | 对当前实测手臂做相对表示，补3维 |
| [6:12] 拇指/食指 | left_control(9) | 绝对连续关节，补3维 |
| [12:17] 中指/图中Ring | lower_body(7) | 绝对连续关节，补2维 |

原数据把J9–J11命名为`little_j1–j3`，此处按图片J9–J11的通道范围处理，不重命名或改写Parquet。两个规则gripper组均为padding/no-op。模型布局仍是9+1+9+1+7；输出可通过`postprocess(...)["action_17d"]`取回原17维顺序。既有推理接口仍返回物理部件字典。

历史输入为6帧、1秒步距，三个相机槽位共18帧；保留发布配置的`temporal_freq=4`、`mem_frame_drop_prob=0.3`。32步动作从当前时刻开始，不因历史帧数量裁掉前5步。

## 关节边界

SG100取用户图片：J1[0,125]、J2[-150,0]、J3[-60,90]、J4[-90,0]、J5[0,125]、J6[-60,90]、J7[0,125]、J8[-60,90]、J9[0,180]、J10[0,125]、J11[-60,90]，单位度，内部转为弧度。

RM65取用户确认的现有实机控制端：下限为`[-3.106,-2.2689,-2.356,-3.106,-2.234,-6.28]` rad，上限为相反数。来源为现有`rm65_real.py`导入并返回的`RM65_JOINT_LOWER_RAD/UPPER_RAD`，定义于`rm65_sim.py`。本仓库不依赖该工程的本机路径。需要变更时通过processor的`joint_limits`配置显式覆盖。

`JointBounds.decode`先还原实测state，再将手臂绝对边界换成`L-state_last/U-state_last`。对每个关节计算边界在原归一化空间的值，在逆归一化之前限幅；逆归一化、手臂绝对角度还原之后再次限幅。NaN动作或非有限观测明确报错，±Inf预测先被限制到有限边界。AR整组缺失的-100标记按当前测量姿态保持。

记录标签和观测均不裁剪。默认仍用实测更稳定的`z-score`；可通过`G05_NORM_MODE=z-score-tail`进行对照，边界在两种模式下均生效。限位控制不能代替轨迹、碰撞、接触或真机闭环验证。

## 官方checkpoint目录与训练环境变量

先按仓库根目录`训练说明.md`（已汇总官方README）配置训练环境与依赖。正式训练沿用官方Python3.10/torch/transformers等要求；本次CPU检查的Python3.12环境不是推荐的正式训练环境。

官方资源必须放在仓库默认位置，不再由环境变量指定权重路径：

```text
checkpoints/action_tokenizer.pt
checkpoints/qwen3_5_2b_base_processor/
checkpoints/g05-base/checkpoints/model_state_dict.pt
```

保留g05-base旁的`.hydra/config.yaml`与`dataset_stats.json`。其他官方checkpoint的完整目录结构、未来下载命令与LIBERO sidecar链接说明见根目录`训练说明.md`。当前只预建目录，没有下载或复制模型文件。

以下值故意留空，应在训练机器的shell或作业环境中填写：

```bash
export G05_DATASET_DIR=       # 含meta/、data/、videos/的LeRobot v2.1根目录
export G05_OUTPUT_DIR=        # 可写的训练输出根目录
export WANDB_PROJECT=        # 自己的W&B项目；不设置时默认G0.5_665
export WANDB_ENTITY=         # 可选，自己的账号/团队；不设置时使用已认证账号
# WANDB_API_KEY由你们的环境注入；脚本不调用wandb.login，不保存token。
```

激活训练环境后，在仓库中运行：

```bash
bash scripts/run/finetune_665.sh model.max_epochs=null model.batch_size=8 model.max_steps=10000
```

示例中的batch与训练步数是可覆盖的运行参数，不是已验收的训练配方。单机GPU数用`NPROC_PER_NODE`设置；其余原生Hydra参数可继续传入。脚本先核对数据schema，再复用原训练入口。

默认`val_set_proportion=0`可直接检查只有一个episode的示例，此时评估复用训练episode，不是独立验证。正式多episode训练请设置`G05_VAL_PROPORTION=0.05`或传入`data.val_set_proportion=0.05`，并确认训练split非空。默认重新计算本任务的统计量并保存`dataset_stats.json`，不套用其他机器人的统计量；复用自己已核验的统计文件可显式传入`datastatics_path`。

恢复训练应指定`resume_ckpt`，并使用同一实验名/输出目录以找到`wandb_id.txt`。此任务最终checkpoint保留optimizer、scheduler、dataloader位置和实际samples_seen，而非覆盖成只能推理的文件。GPU恢复演练仍需在正式环境验证。

## W&B记录

复用已有Accelerator/W&B初始化，直接读取环境认证。保留G0.5的CE/FM、动作token准确率和评估指标，补齐π0.5同类记录：

- `loss`、`learning_rate`、`grad_norm`、`step/global_step`、`time_per_step`；
- 按实际batch计数的`samples_seen`、`equivalent_epochs`，含分布式规模与梯度累积；
- CPU峰值RSS、GPU当前/峰值allocated与reserved显存；
- 首批`camera_views`、配置与`run_manifest.json`中的版本/关节范围/样本量；
- `checkpoint_step`、checkpoint体积、保存完成状态、备份验证状态；
- 各部件边界处理比例，以及`rollout/*_bounded_action_l1`。原始未限幅物理误差同时保留，标签不裁剪。

本地同步保留`training_metrics.jsonl`、`checkpoint_metrics.jsonl`与`wandb_id.txt`。官方checkpoint为一个组合.pt文件，所以`checkpoint/total_bytes`是实际文件大小，`model_bytes/optimizer_bytes`兼容名及`*_tensor_bytes`表示未压缩张量字节数。没有执行外部备份时`backup_verified=0`，不伪报成功。
